# Optional reservation deposit slips

Apply the reservation_deposit_slips migration before deploying. Uploads default to disabled: set `DEPOSIT_SLIPS_ENABLED=true` only after checking shared Supabase storage/egress, Vercel usage and organization GitHub minutes. `DEPOSIT_SLIPS_MAX_BYTES` may lower the default 209715200-byte ceiling; the database never permits a higher ceiling. Each outstanding slot reserves 2 MiB even if its file is smaller, preventing falsified size declarations from bypassing the budget. Existing email, activation, receipts and agreements are independent of this feature.

Partners may store three photos/PDFs per pending portal reservation. Photos are re-encoded locally. File validation decodes photos with Sharp and parses PDFs with pdf-lib; encrypted PDFs are rejected. Files expire independently 30 days after slot creation. Metadata is private except for owner access to ready, unexpired slips on pending reservations. The browser has INSERT-only Storage access to a fresh slot and cannot overwrite/read/list objects directly. Admin viewing requires current MFA. View links last 60 seconds; already issued links may remain usable for that interval after resolution. Previously downloaded files cannot be revoked.

The existing authenticated jobs endpoint runs a bounded cleanup pass after ordinary jobs, even while uploads are disabled. The current main branch retains its Supabase Cron dispatcher, hourly watchdog, authentication, health reports and worker run records; cleanup failures are recorded as DEPOSIT_SLIP_CLEANUP_FAILED. It removes objects using the Storage API, retries failures without releasing reserved capacity, and reconciles objects lacking metadata or arriving after a slot was deleted. Pending reservations are never expired by this cleanup. Deletion records remain for reconciliation; images are not copied into database backups or logs. Cleanup normally follows the hourly worker schedule, which can be delayed by GitHub. Check `depositSlips.failed` and the endpoint's `ok` value using existing ops monitoring; nonzero failures make `ok=false`.

Before enabling, run a real partner upload/view/remove flow and an administrator activation flow with local Storage, plus tests for RLS, concurrent slots, capacity exhaustion, expired uploads and deletion retries. Test mobile photo/PDF selection and confirm text remains readable after compression. Verify storage usage after cleanup and observe worker duration. Disable uploads by removing/setting the flag to false for rollback; keep migration and cleanup deployed. No new paid services or email traffic are introduced. Production account headroom must be checked manually; the local ceiling cannot guarantee an account-wide free-tier allowance.
